\section{Introduction}
% =============================================================================

\subsection{Purpose}
This document is the single, unified Quality Assurance report for the PaleoVox
GUI (v1.0.6). It consolidates every test defined and executed by the three QA
testers --- Alan, \'Angel and Zaid --- into one master plan, with every test case
carrying a color-coded outcome and consolidated execution notes.

\subsection{Sources}
\begin{itemize}
  \item \textbf{Alan Gabriel Amaro Col\'in:} detailed automated execution reports
        for Sections 17--23 (State Management, Widget Defaults, Tooltips,
        Threading, Edge Cases, Temporary Files and Integration Scenarios),
        including the bug-resolution log and verification scripts under
        \texttt{QA/solved\_bugs/}.
  \item \textbf{\'Angel \'Angeles Cort\'es:} the 316-test master plan
        (Window/Layout, Drop Zones, File Loading, t-SNE, 2D Perspectives,
        External Comparison, Reset/About, Status Bar, Error Handling) with manual
        execution annotations.
  \item \textbf{Zaid:} complementary execution runs (File Info, Augmentation,
        t-SNE, 2D, External, Reset) recorded with the automated \texttt{pytest}
        suite, plus the remaining plan sections.
\end{itemize}

\subsection{Test Environment}
\begin{itemize}
  \item \textbf{Operating System:} Linux (X11; headless \texttt{QT\_QPA\_PLATFORM=offscreen} for automated suites)
  \item \textbf{Python:} 3.8+ with PyQt5 5.15.11, Open3D 0.19.0, NumPy 2.0.2,
        SciPy, Matplotlib, scikit-learn, scikit-image, pymeshfix
  \item \textbf{Source under test:} \texttt{paleovox\_gui.py}, \texttt{paleovoxpy.py},
        \texttt{paleovox\_viewer.py}
  \item \textbf{Test data:} \texttt{skull.ply} (1,530,891 verts / 3,000,000 faces),
        \texttt{skull\_deformed.npy} (256$^3$, 86,826 occ),
        \texttt{test\_object\_deformed.npy} (256$^3$, 86,705 occ)
\end{itemize}

\subsection{Status Legend}
Every test in this document is marked with exactly one of the following statuses:

\begin{center}
\begin{tabular}{lll}
\toprule
\textbf{Marker} & \textbf{Meaning} & \textbf{Interpretation} \\
\midrule
\statuspass & Positive test & Executed and passed; behaviour confirmed. \\
\statuswarn & Warning test & Not executed, deferred/manual, or executed with a caveat. \\
\statusresolved & Bug later solved & A defect was found, fixed and verified. \\
\statusbug & Present bug & A defect is present and unresolved in v1.0.6. \\
\bottomrule
\end{tabular}
\end{center}

\smallskip
\noindent
\textit{Consolidation rules:} green marks positive outcomes --- automated
(pytest) PASS runs and manually confirmed ``behaviour as expected''
observations; orange marks defects with a documented fix and verification;
yellow marks deferred/manual edge cases or executed tests whose outcome
carries a warning; red marks defects reproduced against the current code.
Original Spanish execution notes were translated to English.

\subsection{Current Status}
\begin{itemize}
  \item \textbf{Resolved and verified defects (orange):}
        \begin{itemize}
          \item \textbf{WL-004} --- tab labels omitted the ``\&''; replaced with ``-''.
          \item \textbf{WD-006} --- ``Reset All'' did not restore widget defaults; fixed and verified 68/68.
          \item \textbf{TF-BON} --- temp file orphaned when the backend raised; fixed and verified 8/8.
          \item \textbf{DEF-23-01} (affects INT-01, INT-02, VS-008, VC-009) --- Marching-Cubes viewer
                never opened and reopening any viewer crashed; fixed (subprocess viewer + direct launch
                from worker thread) and verified 46/46.
          \item \textbf{AU-015} --- \texttt{erotion\_general} raised \texttt{ValueError}
                when \texttt{increment\_min=1.0}; fixed by clamping the cut-point range (verified).
          \item \textbf{EH-001} --- a corrupted \texttt{.ply} was accepted as an empty mesh
                (0 vertices) instead of raising; the load now validates geometry and shows a
                ``Load Error'' dialog (verified).
        \end{itemize}
  \item \textbf{Closed as by design (yellow):} \textbf{TA-005} --- the GUI is intentionally blocked
        while a viewer window is open (accepted behaviour, no code change).
  \item \textbf{Present bugs (red):} none --- the two previously open bugs (AU-015 and EH-001)
        were resolved in this release (see the resolved list above and Appendix B).
  \item \textbf{Open warnings (yellow):} \textbf{DZ-015/DZ-016} --- the external drop zones keep the
        green ``loaded'' style after a rejected file (cosmetic; still present in v1.0.6);
        \textbf{PL-007}, \textbf{VS-002}, \textbf{VC-012}, \textbf{EH-012} and \textbf{EH-013} ---
        executed tests with minor defects that do not affect the core workflow (Appendix B);
        \textbf{SB-004}, \textbf{D2-005}--\textbf{D2-007}, \textbf{EV-011} and \textbf{TA-005}.
  \item \textbf{Deferred/manual:} EC-014 (HiDPI), EC-015 (deliberately not run --- OOM risk) and
        EC-018 (resize during long operation). The previously unexecuted PL, VS, RC, VC, EH and EC
        suites were executed in October 2026 and are consolidated in the tables above; EC-002
        (1,530,891-vertex mesh) now passes.
\end{itemize}

\subsubsection{Defect Report}
% =============================================================================

\textbf{DEF-23-01 --- Marching-Cubes voxel viewer never opens.}

\textbf{Location:} \texttt{on\_view\_voxels} (\texttt{paleovox\_gui.py:1133-1140})
and \texttt{\_on\_compare\_voxels} (\texttt{paleovox\_gui.py:1233-1256}).

\textbf{Symptom:} When ``Marching Cubes'' is checked, the voxel-to-mesh
conversion runs in a background daemon thread, but the resulting PBR viewer
never appears (INT-01 step 16, INT-02 step 9).

\textbf{Root cause:} after converting in a raw \texttt{threading.Thread}, the
code schedules the viewer with
\texttt{QTimer.singleShot(0, lambda: pv.visualize\_mesh(...))}. A
\texttt{QTimer} created in a plain Python thread has no Qt event loop, so its
timeout never fires --- the \texttt{visualize\_mesh} callback is never invoked.
This was confirmed in isolation: a \texttt{QTimer.singleShot(0, ...)} issued
from a \texttt{threading.Thread} does not fire even while the main thread
processes events.

\textbf{Impact:} The ``View Voxels (Marching Cubes)'' and ``Compare Voxels
(Marching Cubes)'' operations silently do nothing visible (only the status bar
updates). The grid-mode viewers, which call
\texttt{o3d.visualization.draw\_geometries} directly on the daemon thread, are
unaffected.

\textbf{Recommended fix (not applied):} emit a Qt signal (e.g., a
\texttt{pyqtSignal} on the window) from the worker thread after conversion and
connect it to a main-thread slot that calls \texttt{pv.visualize\_mesh}, or use
a \texttt{QThread} so the timer has a valid event loop.

The three integration workflows otherwise behave correctly: mesh and voxel

\section{Bug Resolution Log}
\label{app:buglog}

The QA effort reported four defects (all fixed), one accepted behaviour and
several outstanding warnings. The October 2026 execution of the remaining 95
test cases added one production bug (EH-001) and five minor warnings (PL-007,
VS-002, VC-012, EH-012, EH-013). Both open bugs (AU-015 and EH-001) were fixed
and verified in this release. The fixes were verified with the scripts kept in
\texttt{QA/solved\_bugs/}.

\subsection{DEF-01 / WD-006 --- ``Reset All'' did not restore widget defaults}
\textbf{Status:} \statusresolved \quad \textbf{Section:} 18 (WD-006) \quad
\textbf{Severity:} High

\textbf{Defect:} \texttt{\_on\_reset()} cleared internal state and reset
\texttt{chk\_use\_external}, but did not restore any spinbox, combobox or
checkbox value; widgets kept their modified values after ``Reset All''.

\textbf{Fix:} \texttt{\_on\_reset()} now re-applies the documented defaults
(\texttt{setValue}/\texttt{setCurrentIndex}/\texttt{setChecked}) for all 33
widgets (npoints=100000, dims=256, dilation=2, deform Z/0.85, erode X/0.5,
rotations 0.0, fracture 10, etc.; resets the color combo to Blue, which also
re-triggers \texttt{\_on\_color\_changed}).

\textbf{Verification:} \texttt{test\_widget\_defaults.py} --- 68/68 checks pass
(WD-001 to WD-006).

\subsection{DEF-02 / TA-005 --- Mesh viewers block the GUI}
\textbf{Status:} \statuswarn{} (closed as by design) \quad \textbf{Section:} 20
(TA-005) \quad \textbf{Severity:} Low

\textbf{Behaviour:} \texttt{visualize\_mesh} runs the Open3D event loop on the
main thread, so the GUI is blocked while a mesh viewer is open. The team
considers this intended behaviour (a feature, not a bug); no code change was
made. Voxel viewers (grid and Marching Cubes) are unaffected because they run on
background threads.

\subsection{DEF-03 / TF-BON --- Temp file orphaned when the backend raises}
\textbf{Status:} \statusresolved \quad \textbf{Section:} 22 (TF-BON) \quad
\textbf{Severity:} Low

\textbf{Defect:} the temporary PNG was created before the backend call and
cleanup was wired only to \texttt{dialog.finished}; if the backend raised, the
handler showed an error box but never deleted the temp file
(\texttt{\_on\_generate\_tsne}, \texttt{\_on\_generate\_2d\_single},
\texttt{\_on\_generate\_2d\_comparison}).

\textbf{Fix:} added the \texttt{\_safe\_unlink(path)} helper (guarded by
\texttt{os.path.exists} + \texttt{OSError} catch) and a \texttt{finally} clause
that unlinks the temp file on success, backend failure and early returns.

\textbf{Verification:} \texttt{test\_temp\_files.py} --- 8/8 checks pass
(TF-001 to TF-007 + bonus).

\subsection{DEF-04 / DEF-23-01 --- Marching-Cubes voxel viewer never opened (two sub-defects)}
\textbf{Status:} \statusresolved \quad \textbf{Sections:} 23 (INT-01/INT-02),
View \& Save (VS-008), Voxel Comparison (VC-009) \quad \textbf{Severity:} High

\textbf{Sub-defect 1 (crash):} Open3D's \texttt{gui.Application} is single-use
per process; after the first PBR viewer closed, a second \texttt{app.run()}
segfaulted. \textbf{Fix:} each viewer now runs in a dedicated subprocess via the
lightweight \texttt{paleovox\_viewer.py} (open3d + numpy only);
\texttt{visualize\_mesh} writes temporary \texttt{.ply} files, invokes the viewer
through \texttt{subprocess.run} and cleans up in a \texttt{finally}.

\textbf{Sub-defect 2 (viewer never opened):} the MC conversion ran in a raw
\texttt{threading.Thread} that scheduled the viewer with
\texttt{QTimer.singleShot}, which requires a Qt event loop in the calling thread
and therefore never fired. \textbf{Fix:} \texttt{on\_view\_voxels} /
\texttt{\_on\_compare\_voxels} now call \texttt{pv.visualize\_mesh(...)} directly
from the worker thread (safe, since it only serializes meshes and runs a
subprocess).

\textbf{Verification:} \texttt{test\_integration.py} --- 46/46 checks pass
(INT-01: 26/26, INT-02: 11/11, INT-03: 10/10), including the MC viewer steps.
Sequential viewer reopen and MC window opening were also confirmed on a display.

\subsection{AU-015 --- Erosion with \texttt{increment\_min=1.0} raises \texttt{ValueError}}
\textbf{Status:} \statusresolved \quad \textbf{Section:}
Augmentation (AU-015) \quad \textbf{Severity:} Medium

\textbf{Defect:} in \texttt{erotion\_general} (\texttt{paleovoxpy.py:1680}),
\texttt{restriction = int(min\_val * coefficient * increment\_min)} equals
\texttt{max\_val} when \texttt{increment\_min=1.0}, so
\texttt{np.random.randint(restriction, max\_val)} raises
\texttt{ValueError: low >= high}. Erosion with the maximum increment fails with
an error dialog instead of removing (most of) the object.

\textbf{Reproduction (v1.0.6):} a $10^3$ cube with \texttt{increment\_min=1.0}
raises \texttt{ValueError: low >= high} at the \texttt{np.random.randint} call.

\textbf{Fix:} \texttt{erotion\_general} now clamps the lower bound before
sampling: when \texttt{restriction >= max\_val}, it is set to
\texttt{max\_val - 1}, guaranteeing a non-empty random interval for every
\texttt{increment\_min} in the spinbox range. \textbf{Verification:}
\texttt{increment\_min=1.0} on a $10^3$ cube no longer raises and removes the
top of the object.

\subsection{EH-001 --- Corrupted file loads as an empty mesh}
\textbf{Status:} \statusresolved \quad \textbf{Section:}
Error Handling (EH-001) \quad \textbf{Severity:} Medium

\textbf{Defect:} loading a corrupted \texttt{.ply} does not raise --- Open3D
returns an empty mesh (0 vertices, 0 triangles), so the GUI treats the load as
successful and never shows the expected ``Load Error'' dialog. The user
receives no indication that the file is corrupt.

\textbf{Reproduction (v1.0.6):} loading the corrupted \texttt{.ply} fixture via
the main drop zone produced a 0-vertex mesh and no error dialog
(\texttt{run\_unexecuted\_tests.py}, October 2026).

\textbf{Fix:} \texttt{on\_load\_mesh} now validates the loaded mesh after
\texttt{pv.load\_mesh()} and raises \texttt{ValueError} when the mesh has 0
vertices or 0 triangles, which the existing \texttt{try/except} surfaces as the
``Load Error'' dialog. \textbf{Verification:} a corrupted \texttt{.ply} now
shows the ``Load Error'' dialog and leaves the previous state untouched.

\subsection{DZ-015 / DZ-016 --- External drop zone stays ``loaded'' after a rejected file}
\textbf{Status:} \statuswarn{} (present warning in v1.0.6) \quad \textbf{Section:}
Drop Zone (DZ-015, DZ-016) \quad \textbf{Severity:} Low (cosmetic)

\textbf{Defect:} \texttt{DropZone.dropEvent} / \texttt{mousePressEvent}
(\texttt{paleovox\_gui.py:74--89}) apply the green ``loaded'' style \emph{before}
validation. When a non-\texttt{.npy} file is rejected on the external zones (or
any load fails), the error dialog appears but the drop zone keeps the green
style.

\textbf{Recommendation:} reset the zone to ``idle'' (or restore the previous
style) when the load handler rejects the file.

\subsection{October 2026 run --- minor warnings (PL-007, VS-002, VC-012, EH-012, EH-013)}
\textbf{Status:} \statuswarn{} (present warnings in v1.0.6) \quad
\textbf{Sections:} Pipeline, View \& Save, Voxel Comparison, Error Handling

The October 2026 execution of the remaining 95 test cases surfaced five minor
defects that do not affect the core PaleoVox workflow and are therefore kept as
warnings rather than production bugs:

\begin{itemize}
  \item \textbf{PL-007} --- re-running ``Mesh $\rightarrow$ Voxels'' does not
        clear \texttt{reconstructed\_mesh}, so a stale reconstruction can
        persist after the voxel state is replaced.
  \item \textbf{VS-002} --- the White and Gray display colours differ from the
        specification (observed White $=$ (0.9, 0.9, 0.9), Gray $=$
        (0.5, 0.5, 0.5)); purely cosmetic.
  \item \textbf{VC-012} --- with a \texttt{.npy} loaded, ``Compare Voxels'' is
        enabled although the specification expects it disabled; the code
        behaviour matches SM-011 (a spec/code mismatch, not a code defect).
  \item \textbf{EH-012 / EH-013} --- exceptions raised in the deferred mesh
        viewer launch (\texttt{QTimer.singleShot}) and in the voxel-comparison
        daemon thread are not caught by the error handler, so no dialog is shown
        in those rare failure paths.
\end{itemize}

\textbf{Recommendation:} address PL-007 (clear the state on re-voxelization) and
the EH-012/EH-013 handling gaps in a future maintenance release; VS-002 and
VC-012 can be resolved by aligning the specification (or the colour constants)
with the code.
